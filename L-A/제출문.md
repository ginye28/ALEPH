## 첨부 파일 (1개)

- `진혜정_마지막과제A_제출.zip` — 안에 `진혜정_이력서_자기소개서_경력기술서.docx`(제출 문서), 같은 내용의 `.pdf`, `장치/` 폴더(실행 소스·README·input·마지막 결과 out·두번실행비교.md)

## 재현·통과 확인 4가지

어디서 확인하나요: 공개 사이트 https://aleph-intro.vercel.app 와 첨부한 ZIP(진혜정_마지막과제A_제출.zip) — 안에 문서 DOCX(같은 내용 PDF 포함)와 장치/ 폴더
무엇을 하나요(3단계 이내): 1) 새 시크릿 창에서 사이트를 열고 첫 화면 → 이야기(#story) → 숫자로 보면(#numbers) → 대표작(#works) → 이력서(#resume) 순서로 내려 봅니다. 2) ZIP을 새 폴더에 풀고 진혜정_이력서_자기소개서_경력기술서.docx를 엽니다: 1~2쪽 이력서(연락·교육·대표작·기술·기록 숫자), 3~4쪽 자기소개서(사이트 이야기와 같은 원본), 5쪽 경력기술서(과제마다 능력·상황·행동·결과). 3) 같은 ZIP의 장치/ 폴더에서 README.md의 세 단계대로 `node refresh.mjs`를 두 번 실행합니다.
무엇이 보이면 통과: 첫 화면에 이름 「진혜정」과 "…끝까지 확인하는 사람"으로 끝나는 한 줄 소개가 보입니다. 이야기는 2012 → 2019 겨울 → 2026 봄 → 2026.07 → 2026.08.11 → 2026.08.31→09.01 → 지금으로, 토막마다 날짜가 있습니다. 숫자 칸 4개(출석 29/29, 아침·저녁 점검 29/29, 저녁 실천 27/28, 낸 과제 11/13)에는 모두 출처(내 출석 기록·리추얼 기록·내 제출 현황)가 붙어 있고, 테두리 강조 칸 27/28은 8/31 장면과 링크로 짝지어져 있습니다. 대표작에는 10번 논문 링크와 13번 앱 자리(9/23 시작 예정)가 있습니다. 장치는 두 번 돌려도 out/SHA256SUMS가 똑같고, 장치/두번실행비교.md에 적힌 값과도 같습니다.
안 될 때: `node: command not found`나 SyntaxError가 나오면 Node.js 18 이상을 설치하세요. ZIP만 풀어서 장치/ 옆에 site 폴더가 없으면 `--apply`는 반영을 건너뛰고 out/만 만듭니다(정상). DOCX가 열리지 않으면 ZIP 안의 같은 이름 PDF나 사이트 #resume의 PDF(https://aleph-intro.vercel.app/docs/jin-hyejeong-resume.pdf)가 같은 내용입니다.

## AI와 내 판단 3줄

AI에게 맡긴 일: 11번 소설·9번 서사 문서·리추얼 기록을 대조해 이야기 초안을 쓰고 각색한 대목을 사실로 되돌린 표 만들기, 사이트 디자인과 배포, 숫자와 후보 문장을 다시 만드는 장치 작성과 두 번 실행 비교, GitHub 저장소를 읽어 기술 목록 뽑기, 문서(DOCX·PDF) 만들기, 경력기술서 과제별 능력 연결 다듬기.
내가 판단한 일: 한 줄 소개에서 "흔들렸다"를 빼고 지금 문장을 고른 것, 8/17 공휴일·풀출석·국비 수료(8/14, 8/11부터 ALEPH로 옮겨 출석 80% 이상으로 수료) 같은 사실 확인, 공개할 연락 수단으로 구직용 메일을 새로 만든 것, 사이트에 올릴 기록 문장 9개를 직접 승인한 것.
AI 말을 안 들은 일: '일부 실천'도 실천으로 세고 싶었지만, AI는 과제 기준(작은 숫자를 그대로 쓰는 편이 믿음직하다)을 들어 27/28을 그대로 두자고 했습니다. 저는 숫자는 바꾸지 않되 첫 화면에서는 '28번 점검 · 실천 27 · 일부 실천 1'로 보이게 하는 절충을 골랐고, 27/28과 8/31 장면을 짝지은 칸은 아래 「숫자로 보면」에 남겼습니다.
