# 원자료 — 오픈소스 WebAuthn 구현체 횡단 조사 (실험 B)

**조사일**: 2026-09-10
**조사 방법**: 각 구현체의 공개 소스(GitHub raw 파일) 및 공식 API 문서를 직접 열람. 2차 해설 글은 근거로 삼지 않으며, 소스에서 확인되지 않은 항목은 "확인 불가"로 적는다.
**표본 수**: 10개 (설계서 §3의 목표치와 일치)

## 측정 항목

- **M1** — 라이브러리가 **등록** 검증 결과에서 BE/BS를 호출자에게 노출하는가
- **M2** — 라이브러리가 **인증** 검증 결과에서 BE/BS를 호출자에게 노출하는가
- **M3** — 기본 저장 모델 또는 공식 예제가 그 값을 **저장**하는가
- **M4** — 인증 시 그 값을 **재확인·갱신**하는가

## 1. SimpleWebAuthn (TypeScript / Node) — v13.3.3

| 항목 | 판정 | 근거 |
|---|---|---|
| M1 | 예 | `verifyRegistrationResponse`가 `registrationInfo.credentialDeviceType`·`credentialBackedUp` 반환 |
| M2 | 예 | `esm/authentication/verifyAuthenticationResponse.js` 152행 `parseBackupFlags(flags)` 호출, 163–164행에서 반환 객체에 포함. 타입 정의 `.d.ts` 60–61행 |
| M3 | **아니오** | 공식 예제 `example/index.ts`가 저장하는 값: `{ id, publicKey, counter, transports }` |
| M4 | **아니오** | 공식 예제는 인증 후 `dbCredential.counter = authenticationInfo.newCounter`만 수행 |

플래그 비트 정의(`esm/helpers/parseAuthenticatorData.js` 18–23행): `up: 1<<0`, `uv: 1<<2`, `be: 1<<3`, `bs: 1<<4`, `at: 1<<6`, `ed: 1<<7`.
`parseBackupFlags`는 BE=0·BS=1 조합에 대해 `InvalidBackupFlags` 예외를 던진다.

*확인 방식*: 로컬에 설치된 `node_modules/@simplewebauthn/server` 소스 직접 열람 + GitHub 공식 예제 파일.

## 3. go-webauthn (Go)

| 항목 | 판정 | 근거 |
|---|---|---|
| M1 | 예 | 자격증명 구조체의 `Flags`에 포함 |
| M2 | **예 — 라이브러리가 능동적으로 처리** | `webauthn/login.go`가 BE 플래그 변경 여부를 검사(`credential.Flags.BackupEligible != ...HasBackupEligible()`), BE=0·BS=1인 불가능한 조합을 거부(`!flags.HasBackupEligible() && flags.HasBackupState()`), 그리고 `credential.Flags = credential.Flags.Update(...)`로 갱신 |
| M3 | 구조적으로 유도됨 | 갱신된 `*Credential`을 호출자에게 돌려주므로, 호출자가 이를 저장하는 것이 자연스러운 사용 방식 |
| M4 | **예** | 위와 같이 매 로그인마다 라이브러리가 직접 검사·갱신 |

**본 조사에서 확인된 가장 적극적인 구현.** 다른 구현들이 값을 "노출"하는 데 그치는 반면, 이 구현은 규격의 불변식을 강제하고 상태를 스스로 갱신한다.

## 10. fido2-lib (Node)

| 항목 | 판정 | 근거 |
|---|---|---|
| M1 | **아니오** | `lib/parser.js`의 플래그 파싱이 BE·BS 비트를 예약 비트로 취급 |
| M2 | **아니오** | 위와 같음 |
| M3 | 아니오 | 노출되지 않으므로 저장 불가 |
| M4 | 아니오 | 위와 같음 |

해당 코드:

```javascript
if (flags & 0x01) flagsSet.add("UP");
if (flags & 0x02) flagsSet.add("RFU1");
if (flags & 0x04) flagsSet.add("UV");
if (flags & 0x08) flagsSet.add("RFU3");   // ← BE 비트
if (flags & 0x10) flagsSet.add("RFU4");   // ← BS 비트
if (flags & 0x20) flagsSet.add("RFU5");
if (flags & 0x40) flagsSet.add("AT");
if (flags & 0x80) flagsSet.add("ED");
```

WebAuthn Level 3 기준으로 `0x08`은 BE, `0x10`은 BS이나 이 구현은 둘 다 RFU(예약)로 이름 붙여 두었다. **신호가 개발자에게 도달조차 하지 않는 유일한 사례.**
