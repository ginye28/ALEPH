## 한 줄 요약

WebAuthn은 자격증명이 클라우드에 백업된 상태인지(BS 플래그)를 매 인증마다 서비스에 알려 줍니다. 이 값은 시간이 지나면 바뀔 수 있어 등록 때 한 번 보는 것으로는 부족합니다. 실제로 배포된 시스템에서 백업 상태를 0에서 1로 바꿔 가며 30회 측정한 결과, **전송되는 플래그는 분명히 바뀌었지만 서버의 응답과 저장 상태는 10회 전부 완전히 같았습니다.** 다만 오픈소스 구현체 10개를 조사하니 이것이 보편적이지는 않았고, 갈림길은 "개발자가 알아서 해야 하는가, 기본값이 해 주는가"였습니다.

## 실험 A를 다시 돌려 보려면

측정 스크립트는 측정 대상 시스템(`portfolio-passkey`, 8번 과제 결과물)의 브라우저 하네스를 재사용하므로 **저장소 전체가 필요합니다.** 이 ZIP만으로는 실행되지 않습니다. 원자료는 이 ZIP 안에 그대로 들어 있으므로, 실행 없이 결과만 확인하려면 `원자료-*.json`을 열어 보면 됩니다.

저장소: https://github.com/ginye28/ALEPH (`10/` 폴더)

```bash
# ① 측정 대상 서버를 띄운다
cd 8/portfolio-passkey && npm install && npm run dev

# ② 다른 창에서 측정을 실행한다 (로컬 서버, 10회 반복)
node 10/측정-BE-BS.mjs http://localhost:5179 10

# ③ 공개 배포본으로 대조한다 (1회)
node 10/측정-BE-BS.mjs https://aleph-passkey.vercel.app 1
```

시나리오 3의 네 항목이 모두 `10/10`으로 나오면 논문의 결과가 재현된 것입니다. 자세한 통과 기준과 실패 시 화면은 `논문.md`의 부록 A에 있습니다.
