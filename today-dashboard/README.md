# 오늘의 진짜 정보판

**<https://aleph-dash.vercel.app>**

실제로 변하는 데이터 한 가지(서울 현재 기온)를 **값·단위·출처·조회 시각**과 함께 보여주고, 날짜별 기록과 **이전 기록 대비 변화**를 확인하는 개인 정보판입니다.

설계 근거는 [오늘의-진짜-정보판-설계도.md](../오늘의-진짜-정보판-설계도.md)에 있습니다.

---

## 실행

```bash
npm install
```

```bash
npm run dev
```

빌드는 `npm run build`, 배포는 Vercel(`vercel.json`의 SPA 리라이트)을 씁니다.

## 검증 안내서

**어디로 가나요** — <https://aleph-dash.vercel.app> (설치·로그인 없음)

**무엇을 하나요** (3단계)

1. 맨 위 카드에서 현재값·단위·조회 시각을 확인한다.
2. **출처** 링크를 누른다.
3. 아래로 내려 **이전 기록과의 차이**와 **날짜별 기록**을 확인한다.

**무엇이 보이면 통과인가요**

- 1단계: 숫자·단위(`°C`)·출처·조회 시각(KST)이 스크롤 없이 한 화면에 보인다.
- 2단계: 새 탭에 Open-Meteo 원자료 JSON이 열리고, 그 안의 `current.temperature_2m` 값이 화면의 현재값과 같다.
- 3단계: 차이·방향(▲/▼)·단위가 한 줄에 보이고, 날짜별 기록에 **서로 다른 날짜가 중복 없이 2건 이상** 있다.

**안 될 때**

- 값이 안 보이면 **다시 확인**을 누른다.
- 출처가 안 열리면 브라우저의 팝업/새 탭 차단을 해제한다.
- 차이가 안 보이면 **점검 도구 열기 → 지난 날짜 다시 불러오기**를 누른다.

## 장애 상태 직접 보기

| 주소 | 무엇이 보이나요 |
|------|-----------------|
| `?debug=1` | 점검 도구가 열린 채 시작합니다. 장애 5종 버튼을 각각 누르면 상태 문구·색이 서로 다르게 바뀌고, 값은 마지막 정상값이 `오래된 데이터` 표시와 함께 남습니다. |
| `?fail=auth` | 첫 조회부터 실패한 상태 — **마지막 정상값이 하나도 없을 때** 값을 지어내지 않고 빈 상태를 보여줍니다. `다시 확인`을 누르면 정상으로 복구됩니다. |

`?fail=`에는 `timeout` · `auth` · `rateLimit` · `offline` · `formatChange`를 넣을 수 있습니다. 두 파라미터는 함께 쓸 수 있습니다(`?debug=1&fail=auth`).

## 알아둘 설계 결정

**어제 값을 하루 기다려서 얻지 않습니다.** Open-Meteo는 `past_days` 파라미터로 지난 날짜의 실제 관측값을 같은 응답에 함께 돌려줍니다. 다만 그 값의 **조회 시각은 오늘**이므로, 기록마다 `origin`을 남겨 화면에서 구분합니다.

- `직접 조회` — 오늘 실제로 조회해 저장한 값
- `출처의 지난 기록` — 같은 응답에 들어 있던 지난 날짜 값

**날짜별 기록은 매일 09시 KST 값으로 고정합니다.** 두 날짜를 같은 시각끼리 비교해야 변화량이 의미를 갖고, 채점자가 원자료 JSON에서 같은 두 숫자를 직접 찾아 대조할 수 있습니다. 맨 위 카드의 **현재값**은 이와 별개로 지금 이 순간의 값입니다.

**아직 오지 않은 시각의 값은 저장하지 않습니다.** Open-Meteo는 예보 API라 오늘 남은 시간의 값도 함께 주는데, 이것을 관측값처럼 저장하면 없는 값을 지어내는 것이 됩니다. `hourly.time` 문자열을 `current.time`과 비교해 걸러냅니다(둘 다 같은 형식의 KST 문자열이라 사전순 비교가 곧 시간순 비교입니다).

**비밀값이 0건인 이유는 관리를 잘해서가 아니라 존재하지 않기 때문입니다.** 인증키가 필요 없는 출처를 고른 것이 카드 2의 답입니다.

## 증빙과 보고서 생성

증빙 화면과 제출 보고서는 손으로 캡처하지 않고 명령으로 만듭니다.

```bash
BOARD_URL=https://aleph-dash.vercel.app node tools/capture.mjs
```

헤드리스 브라우저로 공개 주소를 실제로 조작해 증빙 15장을 찍고, 그동안 나간 네트워크 요청 주소를 전수 기록해 `정보판 증빙 화면/촬영 기록.json`에 남깁니다.

```bash
node tools/report.mjs
```

촬영 기록을 읽어 `오늘의 진짜 정보판 제출 보고서.pdf`를 만듭니다. 공개 주소는 촬영한 주소를 그대로 씁니다. `BOARD_URL`을 주지 않으면 개발 서버(`http://localhost:5175`)에서 촬영합니다.

## 실측 검증 기록 (2026-08-24 16:32 KST)

공개 주소 <https://aleph-dash.vercel.app> 에서 `tools/capture.mjs`로 자동 촬영하며 확인한 결과입니다.
아래 수치는 손으로 적은 것이 아니라 `정보판 증빙 화면/촬영 기록.json`에 남은 값입니다.

**빌드**

- `npm run lint` 통과 (경고 0건), `npm run build` 성공
- 실행 중 콘솔 오류 0건

**카드 1 · 값의 맥락**

- 현재값 `30.9 °C`, 단위·출처·마지막 정상 조회 시각(`2026. 08. 24. 16:31:30 KST`)·자료 기준 시각(`08월 24일 16시`)이 한 화면에 표시됨

**카드 2 · 비밀키와 호출 경로**

- 화면의 출처 링크 `href`가 실제 호출 주소와 완전히 일치
- 원자료 응답의 `current.temperature_2m` = **30.9** (기준 `2026-08-24T16:30`) → 화면값 `30.9 °C`와 문자 단위로 일치
- 소스·빌드 결과물에서 `api_key` · `secret` · `token` · `Bearer` · `serviceKey` 패턴 **0건**, `.env` 파일 없음
- 촬영 중 나간 요청 178건의 외부 호스트는 `api.open-meteo.com` · `fonts.googleapis.com` · `fonts.gstatic.com` 셋뿐

**카드 3 · 실패를 구분해 보여주기**

| 장애 | 화면 문구 | 마지막 정상값 |
|---|---|---|
| timeout | `오래된 데이터 · 응답이 지연되고 있어요` | 30.9 유지 |
| auth | `오래된 데이터 · 접근 권한에 문제가 있어요` | 30.9 유지 |
| rateLimit | `오래된 데이터 · 요청이 많아 잠시 제한됐어요` | 30.9 유지 |
| offline | `오래된 데이터 · 인터넷 연결을 확인해주세요` | 30.9 유지 |
| formatChange | `오래된 데이터 · 출처 응답 형식이 바뀌었어요` | 30.9 유지 |

- 다섯 경우 모두 문구·색이 다르고, 값은 마지막 정상값이 그대로 남음
- `다시 확인` 한 번으로 모두 `현재 자료 · 정상`으로 복구됨
- `?fail=auth`로 정상값이 없는 상태 확인 — `아직 정상값이 없습니다`가 뜨고 출처·시각이 모두 `-`. 값을 지어내지 않음

**카드 4 · 하루 한 번 기록**

- 첫 조회에 4건 저장: `08-24 직접 조회` / `08-23·08-22·08-21 출처의 지난 기록`
- `다시 확인`을 다시 눌러도 4건 그대로, **중복 0건**
- 오늘 17시~23시 예보값은 `current.time` 비교로 제외됨 (예보를 관측값으로 저장하지 않음)

**카드 5 · 어제와 비교 검증**

- 기준 시각 09시 값: `08-21 23.8` / `08-22 23.9` / `08-23 25.2` / `08-24 26.3` (°C)
- 변화 계산 `26.3 − 25.2 = 1.1000000000000014` → 화면 표기 `+1.1 °C (증가)`
- 손계산 `26.3 − 25.2 = 1.1`과 일치. 계산식이 화면에 그대로 노출됨

> 값은 매 촬영마다 달라집니다. 12:04 촬영본은 현재값 `31.0`, 08-24 09시 `26.4`였고,
> 16:32 촬영본은 `30.9` · `26.3`입니다. 출처가 지난 시각 값을 재분석해 갱신하기 때문이며,
> 보고서는 촬영 기록에서 값을 읽으므로 두 수치가 어긋나지 않습니다.
