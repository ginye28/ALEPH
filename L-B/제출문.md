# 마지막 과제 B — 제출 칸에 넣을 내용

## 카드 1 · 앱 한 문장과 할 일 세 가지

**앱 한 문장 (BRB-C01)**
패스키 로그인을 만드는 개발자가 로그인 응답을 넣으면, 이 앱은 10번 논문이 확인한 규칙(규격 §7.2 단계 18·19, 5.2절 적응형 인증, 6장 3단계 점검, 표 14 라이브러리 판정)으로 백업 상태(BE/BS) 전이를 판정하고 서버에 빠진 저장·대조 단계를 알려 줍니다.

- 쓰는 논문 결과: "전이가 실제로 일어난 10/10에서 서버 상태 무변화", "신호가 끊기는 곳은 라이브러리와 응용 사이", "BS 전이는 막지 말고 되돌릴 수 없는 동작에만 한 단계 더"

**사용자가 할 일 세 가지 (BRB-C02)**
1. 로그인 응답(authenticatorData 또는 플래그 바이트)을 넣어 BE·BS를 읽는다.
2. 서버가 보관한 BE·BS와 지금 하려는 동작을 골라 통과·한 단계 더 확인·거부 판정과 저장할 값을 받는다.
3. 쓰는 라이브러리·응용을 고르고 세 질문에 답해 빠진 단계와 고치는 코드를 받는다.

## 재현·통과 확인 4가지

어디서 확인하나요: 공개 URL https://aleph-bs-check.vercel.app (로그인 없음). 같은 앱이 ZIP의 bs-check/ 폴더에 있고 index.html을 더블클릭하면 인터넷 없이도 열립니다. 12번 사이트 https://aleph-intro.vercel.app/#works 대표작 두 번째 카드에 연결되어 있습니다.
무엇을 하나요(3단계 이내): 1) 첫 화면 01 칸의 예시 버튼(「등록 뒤 동기화를 켰다」「동기화를 껐다」「기기 전용 키」「규격 위반 be:0, bs:1」「보관값이 없는 서버」)을 차례로 누르거나 0x1d 같은 값을 직접 넣습니다. 2) 02 칸에서 보관한 BE·BS와 "평소 로그인 / 되돌릴 수 없는 동작"을 바꿔 봅니다. 3) 03 칸에서 「Spring Security WebAuthn」이나 쓰는 라이브러리를 고르고 세 질문에 답합니다.
무엇이 보이면 통과: 첫 화면에 논문 제목과 "이 앱은 패스키 로그인을 만드는 개발자가…" 한 문장이 있습니다. 예시별 판정이 논문 규칙대로 나옵니다 — 동기화 켬+되돌릴 수 없는 동작 → 「한 단계 더 확인」, 동기화 끔 → 「통과」(ever_backed_up은 참 유지), 기기 전용 → 「통과」, be:0·bs:1 → 「거부」, 보관값 없음 → 「통과」와 "전이를 알 수 없습니다" 경고. 03 칸에서 Spring Security를 고르면 「2·3단계 빠짐」과 고치는 SQL·JS가 나옵니다. hello!!·999·AAAA 같은 잘못된 값을 넣으면 앱이 멈추지 않고 안내 문장이 나옵니다. ZIP 폴더에서 `node test.cjs`를 실행하면 "29개 모두 통과"가 나옵니다.
안 될 때: 화면이 비면 새로고침합니다(자바스크립트가 꺼져 있으면 동작하지 않습니다). `node test.cjs`는 선택이며 Node.js 18 이상이 필요합니다. 앱 자체는 브라우저만 있으면 됩니다.

## AI와 내 판단 3줄

AI에게 맡긴 일: 논문(규격 §7.2 단계 18·19, 5.2절, 6장, 표 14·16)을 판정 규칙으로 옮기는 코드 작성, 화면 구성, 예시 값 만들기, 잘못된 입력을 포함한 규칙 확인 29개 작성, 공개 배포와 12번 사이트·이력서 문서의 대표작 자리 연결.
내가 판단한 일: 돕는 사람을 "패스키 로그인을 만드는 개발자"로 정한 것, 논문 결론대로 BS 전이는 로그인을 막지 않고 되돌릴 수 없는 동작에만 한 단계 더 요구하게 한 것, "이 앱은 공격자를 잡는 도구가 아니다"(5.1절)를 첫 화면 아래에 밝혀 둔 것, 실제 사용자 자료 대신 만든 예시 값만 쓰기로 한 것.
