# 플랜두씨 다이어리 — 계획한 나와 실제의 나

**<https://aleph-pds.vercel.app>**

공부한 시간을 **분 단위**로 기록하고 고치고 지우고 다시 불러오는 개인 기록기입니다.
입력 화면을 만드는 데서 끝나지 않고, **구조가 바뀌어도 이전 기록을 지키는 법**과
**잘못된 값이 집계를 흔들지 않게 막는 법**을 다룹니다.

설계 근거는 [플랜두씨-다이어리-설계도.md](../플랜두씨-다이어리-설계도.md)에 있습니다.

**이 화면의 자료는 모두 합성입니다.** 실제 개인 기록은 올리지 않습니다.
과제별로 폴더와 배포가 분리돼 있고 서로 건드리지 않습니다.

| 과제 | 폴더 | 공개 주소 |
|---|------|-----------|
| 4 | `today-dashboard/` | <https://aleph-dash.vercel.app> |
| 5 | `handoff-lab/` | <https://aleph-daup.vercel.app> |
| 6 | `plandosee/` | <https://aleph-pds.vercel.app> |

## 기록은 어디에 남나요

브라우저의 `localStorage`에만 남고 **서버로 보내지 않습니다.** 저장 칸은 주소마다 따로라
`localhost:5177`과 공개 주소가 각각 다른 칸을 씁니다. 둘 다 내 컴퓨터 안입니다.

**채점자가 공개 주소를 열어도 자기 브라우저의 빈 저장소를 볼 뿐**이고, 내 기록은 보이지 않습니다.
그래서 실제 5일 사용도 공개 주소에서 하면 됩니다 — 개발 서버를 매일 켤 필요가 없습니다.

다만 브라우저 데이터를 지우면 기록이 사라지니, 며칠에 한 번 **JSON 내보내기**로 파일에 백업해 두세요.

## 검증 안내서

**어디로 가나요** — 공개 주소 (설치·로그인 없음)

**무엇을 하나요** (3단계)

1. **자료 도구**에서 `경계 · 오류 자료`를 누른다.
2. **기록 목록**에서 아무 행의 `수정`을 눌러 시간을 바꾸고 저장한다.
3. `JSON 내보내기`를 누른 뒤 그 파일로 `JSON 가져오기`를 한다.

**무엇이 보이면 통과인가요**

- 1단계 — 주간 요약에 기간(`2026-08-24(월) ~ 2026-08-30(일)`)·합계 `85분`·이번 주 `3건`·보류 `7건`이 보이고, 잘못된 값은 **보류 목록**에 이유와 함께 있다.
- 2단계 — 고친 행 하나만 바뀌고 **주간 합계가 같은 화면에서 함께** 바뀐다.
- 3단계 — 건수가 늘지 않고 `n건은 이미 있어 건너뜀`이 결과 영역에 보인다.

**안 될 때**

- 목록이 비면 `합성 자료 넣기`를 먼저 누른다.
- 가져오기가 실패하면 **결과·오류** 영역의 이유를 읽는다. 기존 기록은 그대로다.
- 전체 삭제 뒤에는 새로고침해도 0건이다.

## 알아둘 설계 결정

**행은 배열 순번이 아니라 `id`로 가리킵니다.** 순번으로 가리키면 정렬이나 필터를 바꾼 순간
수정·삭제가 다른 행에 반영됩니다. 검사 2·3이 이 경계를 지킵니다.

**날짜는 `Date` 객체로 바꾸지 않고 `YYYY-MM-DD` 문자열로 비교합니다.**
`new Date("2026-08-24")`는 UTC 자정으로 해석돼 KST에서 하루 밀립니다. 검사 9가 이걸 봅니다.

**가져오기는 읽기 → 검사 → 통과한 경우에만 쓰기입니다.** 지우고 나서 읽으면 손상 파일 하나가
기존 기록을 통째로 날립니다. 검사 6이 이걸 봅니다.

**잘못된 값은 버리지 않고 보류로 남깁니다.** 조용히 버리면 사용자는 자기 기록이 사라진 줄 압니다.
보류 행은 이유와 함께 화면에 남되 **집계에는 들어가지 않습니다**.

**분 입력에 1440 상한을 둡니다.** 600을 6000으로 잘못 치면 주간 합계가 통째로 망가집니다.
입력 시점에 막는 게 집계에서 걸러내는 것보다 쌉니다.

**수정 폼은 `key`로 다시 마운트합니다.** `useEffect`로 폼을 되돌리면 렌더가 두 번 도는데,
초기값으로 처리하면 한 번이면 됩니다.
