# 짤·카드 스튜디오 — 설계도

이미지와 문구를 조합해 밈·카드·SNS 게시용 이미지를 만들고 파일로 내려받는 제작 도구.

---

## 0. 이 설계도의 기준

과제 체크리스트의 모든 항목은 아래 **세 가지 설계 원칙** 중 하나에서 따라 나온다. 구현 중 판단이 갈리면 이 세 줄로 되돌아온다.

| # | 원칙 | 이 원칙이 막아주는 실패 |
|---|------|------------------------|
| 1 | **좌표는 전부 0~1 정규화로 저장한다.** 픽셀 값은 그리는 순간에만 만든다. | 화면비를 바꾸거나 해상도가 달라지면 문구 위치가 어긋나는 문제 |
| 2 | **그리는 코드는 `renderComposition()` 하나뿐이다.** 미리보기와 저장 파일은 `size` 인자만 다르다. | 미리보기와 내려받은 파일의 배치가 다른 문제 (카드 2의 핵심) |
| 3 | **저장은 "전부 검증 → 통째로 교체"만 한다.** 부분 저장·선반영 금지. | 잘못된 파일을 넣었을 때 기존 템플릿·편집 내용이 사라지는 문제 |

---

## 1. 기술 스택과 구조

기존 `card-matching-game`과 동일한 스택을 쓴다. 새로 배울 것을 늘리지 않고 렌더링 문제에 집중하기 위해서다.

- React 19 + Vite, Emotion(`styles.js` 분리 패턴), Vercel 배포(`vercel.json` SPA 리라이트)
- 라우터는 단일 화면이므로 선택 사항. 편집 화면 하나 + 검증 안내 페이지 정도면 충분하다.
- 서버 없음. 이미지·템플릿 모두 브라우저 안에서만 처리한다. (개인정보 항목의 근거가 된다.)

```
zzal-studio/
├─ index.html
├─ vercel.json                    # SPA 리라이트 (기존과 동일)
└─ src/
   ├─ main.jsx
   ├─ App.jsx
   ├─ pages/
   │  └─ Studio/                  # 편집 화면 (메인)
   ├─ components/
   │  ├─ ImageDropzone/           # PNG·JPEG 불러오기 + 거부 사유 표시
   │  ├─ CanvasPreview/           # 미리보기 캔버스
   │  ├─ RatioSelector/           # 1:1 · 4:5 · 9:16
   │  ├─ TextPanel/               # 문구·위치·크기·색

   ├─ render/
   │  ├─ composition.js           # renderComposition()  ← 단일 진실 원천
   │  ├─ textLayout.js            # 줄바꿈·이모지·자동 축소
```

## 2. 상태 모델

편집 상태와 템플릿은 **같은 모양**이다. 따로 변환하지 않으므로 "저장했더니 복원이 다르게 되는" 경로가 아예 생기지 않는다.

```js
// composition state === template payload
{
  version: 1,
  id: 'uuid',
  name: '기본 밈 자막',

  ratio: '1:1',                  // '1:1' | '4:5' | '9:16'
  background: '#111114',         // 이미지가 못 채운 영역 / JPEG 합성 배경

  image: {
    fit: 'cover',                // 'cover' | 'contain'
    offsetX: 0.5,                // 0~1, 잘라낼 위치(초점)
    offsetY: 0.5,
    scale: 1                     // 1 = 화면비에 맞춘 기본 크기
  },

  text: {
    content: '',
    x: 0.5,                      // 0~1, 글상자 기준점
    y: 0.85,
    align: 'center',             // 'left' | 'center' | 'right'
    sizeRatio: 0.08,             // 캔버스 "높이" 대비 글자 크기
    maxWidthRatio: 0.86,         // 캔버스 "폭" 대비 글상자 최대 폭
    lineHeight: 1.25,
    color: '#FFFFFF',
    stroke: { color: '#000000', widthRatio: 0.006 },  // 밝은 이미지 대비용
    box: {                       // 문구 뒤 띠 — 표·사진 위에서도 읽히게
      color: '#000000',
      opacity: 0,                // 0이면 그리지 않음
      paddingRatio: 0.02
    }
  }
}
```

**이미지 자체는 템플릿에 저장하지 않는다.** 이유 두 가지:
- localStorage 용량(약 5MB)을 사진 한 장이 다 먹는다.
- 저작권을 확인한 이미지만 쓴다는 원칙상, 이미지가 JSON에 실려 밖으로 나가면 관리 범위를 벗어난다.

템플릿은 "배치 설정"이고, 불러오면 문구·위치·색·화면비가 복원되며 이미지는 사용자가 다시 고른다. 이 사실을 화면의 안내 문구에도 적는다.

## 3. 렌더 파이프라인 (카드 1·2의 심장)

```
 상태(state) + 이미지(ImageBitmap)
             │
             ▼
   renderComposition(ctx, state, { w, h })      ← 단 하나의 그리기 함수
             │
      ┌──────┴───────┐
      ▼              ▼
 미리보기 캔버스     내보내기 캔버스
 w=1080,h=1350     w=1080,h=1350
 CSS로만 축소       원본 크기 그대로
      │                  │
      ▼                  ▼
   화면 표시         toBlob → 내려받기
```

핵심은 **미리보기 캔버스도 출력 해상도로 그리고 CSS width/height로만 줄여 보여주는 것**이다. 미리보기를 작은 픽셀로 그린 뒤 출력 때 따로 계산하면, 반올림·줄바꿈·글꼴 힌팅이 달라져 배치가 어긋난다. 같은 픽셀 크기로 두 번 그리면 결과는 정의상 동일하다.

```js
// render/composition.js
export function renderComposition(ctx, state, size) {
  const { w, h } = size;

  ctx.clearRect(0, 0, w, h);
  if (state.background) { ctx.fillStyle = state.background; ctx.fillRect(0, 0, w, h); }

  if (state.bitmap) drawImageFitted(ctx, state.bitmap, state.image, w, h);
  if (state.text.content.trim()) drawText(ctx, state.text, w, h);
}
```

### 내보내기 절차 (순서가 통과 기준이다)

1. `await document.fonts.ready` — 한글 웹폰트가 로드되기 전에 그리면 파일만 다른 글꼴로 나온다.
2. 이미지 디코딩 완료 확인 (`createImageBitmap` await 완료 상태).
3. 오프스크린 캔버스에 `renderComposition` 1회 실행.
4. `canvas.toBlob(cb, 'image/png')` 또는 `'image/jpeg', 0.92`.
5. Blob 크기가 0이면 실패로 처리하고 사유를 표시한다. (빈 파일이 내려가지 않게 한다.)
6. `URL.createObjectURL` → `<a download>` → `revokeObjectURL`.

### 화면비 정의

| 값 | 픽셀 | 용도 |
|----|------|------|
| `1:1` | 1080 × 1080 | 정사각 게시물 |
| `4:5` | 1080 × 1350 | 세로 게시물 |
| `9:16` | 1080 × 1920 | 스토리·릴스 |

가로 폭을 1080으로 고정하면 `sizeRatio`(높이 기준)만으로 세 비율의 글자 크기가 자연스럽게 스케일된다.

## 4. 텍스트 레이아웃 (카드 3의 심장)

한글은 공백 단어 경계가 드물어서 단어 단위 줄바꿈이 통하지 않고, 이모지는 코드 유닛으로 자르면 깨진다.

```js
// render/textLayout.js
// 1) 명시적 \n 으로 먼저 문단을 나눈다.
// 2) 각 문단을 grapheme 단위로 쪼개 폭이 넘칠 때 줄을 끊는다.
//    Intl.Segmenter(ko, { granularity: 'grapheme' })
//    → ZWJ 결합 이모지(👨‍👩‍👧), 피부톤 변형자, 조합형 한글이 쪼개지지 않는다.
// 3) 총 높이가 허용 영역을 넘으면 글자 크기를 0.98배씩 줄이며 재계산한다.
//    하한 sizeRatio 0.03. 잘라내기(ellipsis)는 하지 않는다 — 잘림은 결함이다.
// 4) 결과: [{ text, width }] 줄 배열 + 최종 fontSize
```

- 빈 문구·공백만 있는 문구는 **오류가 아니라 텍스트 레이어 생략**이다.
- `ctx.textBaseline = 'middle'`, `textAlign`은 `state.text.align`을 그대로 쓰고 기준점 `x`는 정렬에 맞춰 해석한다. 미리보기와 출력이 같은 코드를 쓰므로 어긋날 수 없다.
- 문구 뒤 띠(`text.box`)는 줄 배열의 최대 폭 + 여백으로 사각형을 잡아 글자보다 **먼저** 그린다. 캔버스 밖으로 나가지 않게 사각형을 화면 안으로 자른다.
- 위치 조작은 슬라이더와 **미리보기 드래그** 두 가지다. 드래그는 포인터 좌표를 캔버스 표시 크기로 나눠 0~1 값으로 바로 바꾼다 — 미리보기가 CSS로만 줄어 있으므로 비율 계산만으로 충분하다.
- 글꼴 지정: `font: ${weight} ${fontSize}px 'Pretendard', 'Noto Sans KR', system-ui, sans-serif` — 대체 글꼴까지 명시해 이모지 폴백이 조용히 달라지는 것을 막는다.

## 5. 이미지 불러오기와 개인정보

```js
// utils/loadImage.js
const ALLOWED = ['image/png', 'image/jpeg'];

export async function loadImage(file) {
  if (!ALLOWED.includes(file.type)) {
    return { ok: false, reason: 'PNG 또는 JPEG 파일만 불러올 수 있습니다.' };
  }
  if (file.size > 15 * 1024 * 1024) {
    return { ok: false, reason: '15MB 이하 파일만 불러올 수 있습니다.' };
  }
  try {
    const bitmap = await createImageBitmap(file);   // 디코딩 실패 = 위장 파일
    return { ok: true, bitmap };
  } catch {
    return { ok: false, reason: '이미지를 읽지 못했습니다. 파일이 손상됐을 수 있습니다.' };
  }
}
```

**실패해도 기존 상태를 절대 건드리지 않는다.** 호출부는 `ok`가 참일 때만 상태를 교체하고, 거짓이면 사유 문구만 띄운다. (체크리스트: "지원하지 않는 파일을 넣어도 기존 작업이 사라지지 않고 이유가 표시됩니다.")

**메타데이터 제거**: 캔버스에 그려 다시 인코딩하는 순간 EXIF·GPS 정보는 원본에서 승계되지 않는다. 즉 내려받은 결과물에는 위치 정보가 구조적으로 남을 수 없다. 다만 *원본* 이미지 자체도 메타데이터를 지운 사본을 준비해 두고(카드 1의 첫 행동), 제출 증빙 화면에 원본과 결과 파일의 속성 창을 함께 남긴다.

## 6. 템플릿 저장소

```js
// storage/templates.js
const KEY = 'zzal-studio.templates.v1';

load()            // JSON.parse 실패·형태 불일치 → [] 반환 + 경고 1회 (앱은 계속 동작)
saveAll(items)    // 전체 배열을 한 번에 기록
create(state)     // crypto.randomUUID() 부여 후 append
update(id, state) // id 일치 항목 교체 (없으면 실패로 처리, 조용히 추가 금지)
remove(id)        // filter 후 saveAll
```

- 앱 시작 시 `load()` 결과로 목록을 그린다. 화면 목록과 저장 데이터가 갈라지지 않도록, **CRUD 후에는 항상 저장소에서 다시 읽어 화면을 그린다.**
- `update`가 `create`처럼 동작하면 "수정했더니 항목이 하나 늘어나는" 결함이 생긴다. id 조회 실패는 명시적 오류로 처리한다.
- 저장 실패(용량 초과 등)는 무시하지 않고 사유를 표시한다.

## 7. 내보내기 / 가져오기 (카드 5)

### 파일 형식

```json
{
  "app": "zzal-studio",
  "version": 1,
  "exportedAt": "2026-08-21T00:00:00.000Z",
  "items": [ { "id": "...", "name": "...", "ratio": "4:5", "text": { }, "image": { } } ]
}
```

### 검증 규칙 — 하나라도 실패하면 **저장하지 않는다**

| 순서 | 검사 | 거부 문구 |
|------|------|-----------|
| 1 | `JSON.parse` 성공 | 파일 형식이 올바르지 않습니다. |
| 2 | 최상위가 객체이고 `items`가 배열 | 템플릿 파일이 아닙니다. |
| 3 | 항목마다 `name`(문자열, 1자 이상), `ratio` ∈ 지원 목록 | 필수 항목이 빠졌습니다. |
| 4 | `text.x`, `text.y`, `sizeRatio` ∈ [0,1] | 값의 범위가 올바르지 않습니다. |
| 5 | `color`, `stroke.color`가 `#RRGGBB` 형태 | 색상 값이 올바르지 않습니다. |

검증은 **전부 통과한 뒤에 한 번에 교체**한다. 3번에서 걸린 파일 때문에 1·2번 항목이 이미 들어가 있는 상태가 되면 안 된다.

검사용 잘못된 파일 2종을 미리 만들어 둔다.
- `broken-syntax.json` — 닫는 중괄호를 지운 파일 (문법 오류)
- `missing-field.json` — `items[1].ratio`를 삭제한 파일 (필수 항목 누락)

두 경우 모두 **기존 템플릿 목록이 그대로 남아 있는 화면**을 증빙으로 남긴다.

## 8. 극단 입력 12개 검사표

각 항목은 **미리보기와 내려받은 파일을 모두** 확인한다. 표는 `검사 자료 / 예상 결과 / 실제 결과 / 발견 결함 / 수정 후 결과` 5열로 기록한다.

| # | 검사 자료 | 예상 결과 |
|---|-----------|-----------|
| 1 | 한글 200자 (공백 포함 긴 문장) | 자동 줄바꿈 + 글자 크기 축소, 잘림 없음 |
| 2 | 한글·영문·숫자 혼합 | 줄바꿈 위치가 글자 중간에서 어색하게 끊기지 않음 |
| 3 | 명시적 줄바꿈 5줄 | 입력한 줄 수 그대로 유지 |
| 4 | 이모지만 (👨‍👩‍👧‍👦 👍🏽 🇰🇷) | 결합 이모지가 쪼개지지 않음 |
| 5 | 한글 + 이모지 혼합 | 기준선이 흔들리지 않고 겹치지 않음 |
| 6 | 빈 문구 | 텍스트 없이 이미지만, 오류 없음 |
| 7 | 공백만 (스페이스 10개) | 6번과 동일 처리 |
| 8 | 공백 없는 영문 120자 | 문자 단위로 강제 줄바꿈 |
| 9 | 세로 이미지(1080×1920)를 1:1에 | `cover` 기준으로 중앙 정렬, 상하 잘림이 의도대로 |
| 10 | 가로 이미지(1920×1080)를 9:16에 | 좌우 잘림 또는 `contain` 시 배경색 채움 |
| 11 | 투명 배경 PNG | PNG 저장 시 투명 유지, JPEG 저장 시 배경색 합성 |
| 12 | 지원하지 않는 파일 (SVG / GIF / 20MB) | 거부 사유 표시, **기존 편집 내용 유지** |

12개 중 최소 1건은 실제 결함으로 기록하고 수정 전·후 화면을 남긴다. 가장 잘 나오는 후보는 4번(이모지 분리), 8번(무공백 문자열), 11번(투명 → JPEG 검은 배경)이다.

## 9. 카드별 구현 순서와 통과 기준

| 카드 | 만드는 것 | 완료 판정 |
|------|-----------|-----------|
| 1 · 편집과 미리보기 | `loadImage` → 상태 → `renderComposition` 연결, 문구·위치·크기·색 입력 | 값을 한 번 바꾸면 미리보기가 즉시 바뀐다 |
| 2 · 화면과 파일의 일치 | `ratios.js`, 내보내기 절차 6단계, 기준선이 보이는 검사 문구 | 세 비율 각각 미리보기 ≡ 파일 |
| 3 · 극단 입력 검사 | `textLayout.js` 완성, 12개 검사표 | 긴 한글·줄바꿈·이모지에서 잘림·겹침 없음 |
| 4 · 템플릿 관리 | `storage/templates.js` + `TemplateList` | 3개 생성 → 1개 수정 → 1개 삭제 → 새로고침 후에도 유지 |
| 5 · 옮겨 쓰기 | `schema.js` 검증 + 내보내기/가져오기 + 완성 이미지 3장 | 정상 JSON 복원 / 잘못된 파일 2종 거부, 기존 목록 유지 |

카드 순서는 그대로 구현 순서다. 2번을 미루면 3~5번에서 만든 검증 결과를 전부 다시 찍어야 한다.

## 10. 검증 안내서 골격

> **어디로 가나요** — `https://<배포주소>` (설치·로그인 없음)
>
> **무엇을 하나요** (3단계)
> 1. 이미지 고르기를 눌러 PNG 또는 JPEG를 한 장 넣는다.
> 2. 문구를 입력하고 화면비 `4:5`를 고른다.
> 3. 이미지 내려받기를 누른다.
>
> **무엇이 보이면 통과인가요** — 내려받은 파일을 열었을 때 문구의 위치·크기·색·줄바꿈이 화면의 미리보기와 같고, 이미지 비율이 4:5다.
>
> **안 될 때** — 파일이 거부되면 PNG/JPEG인지 확인한다. 내려받기가 되지 않으면 브라우저의 다운로드 차단을 해제한다. 글자가 다른 글꼴로 보이면 새로고침 후 다시 시도한다.

## 11. 미리 대비할 위험

| 위험 | 대응 |
|------|------|
| 웹폰트 로드 전에 저장 → 파일만 다른 글꼴 | 내보내기 직전 `await document.fonts.ready` |
| 투명 PNG를 JPEG로 저장 → 검은 배경 | JPEG 선택 시 `background` 색을 먼저 채우고 그린다 |
| 모바일에서 큰 이미지 메모리 초과 | `createImageBitmap`에 `resizeWidth` 상한(예: 2160) 지정 |
| localStorage 용량 초과 | 이미지를 저장하지 않는 설계로 원천 회피 + 저장 실패 시 사유 표시 |
| 콘솔 오류 잔존 | 캔버스 작업은 전부 `try/catch`로 감싸고 사용자 문구로 변환 |
| 개인정보 노출 | 서버 전송 없음 · 캔버스 재인코딩으로 EXIF 제거 · 저장소에 이름/이메일 저장 안 함 |
